# Quickstart test: fresh isolated stack

What this is: the output of one real run of `docker compose up --build` on branch `day3-nag`, in a separate
compose project (`requiem-fresh`) with every host port shifted so it could not touch another stack on the same
machine. Nothing below is edited except trimming the Requiem log to the interesting lines. Run on Windows 11,
Docker Engine 29.7.2 (Docker Desktop) (8 GB given to Docker; the whole stack used about 1.7 GB of it).

Command (ports shifted by +100 through the overridable env vars; the first build also pulled the images):

```
# .env.fresh: FLAGSMITH_PORT=8100 GRAFANA_PORT=3130 PROMETHEUS_PORT=9190 SHOP_PORT=8190
#             OTLP_GRPC_PORT=4417 OTLP_HTTP_PORT=4418 POSTGRES_CONTAINER_NAME=requiem_fresh_postgres
docker compose -p requiem-fresh --env-file .env.fresh -f deploy/docker-compose.yml up --detach --build
docker compose -p requiem-fresh --env-file .env.fresh -f deploy/docker-compose.yml --profile loadgen up --detach loadgen
```

Wall time was not measured precisely; the bootstrap waited for Flagsmith's migration, which is the slow step.

## Pass criteria

| Criterion | Result | Evidence below |
|---|---|---|
| Shop answers `/health` | PASS (HTTP 200) | "Checks" |
| Requiem's loop logs a check | PASS | "Requiem log" |
| Flagsmith shows the two experiments | PASS (both created by the bootstrap service) | "Checks" |
| Grafana answers | PASS (HTTP 200, database ok) | "Checks" |

Extra, not required: with the load generator on, a fault was switched on in the shop (`POST /admin/fault`) and
Requiem killed `new_checkout` after 3 breached windows (visible in the log; the experiment shows `paused`).
The traffic is generated by `loadgen`, not real users.

## Teardown

`docker compose -p requiem-fresh --env-file .env.fresh -f deploy/docker-compose.yml down -v` removed the
volumes and every container except `loadgen`: a profile service is only touched when the profile is named, so
the first `down` printed "Network ... still in use". A second `down -v` with `--profile loadgen` removed it and
the network. After that `docker compose ls` showed only the other project (`deploy`, 6 containers, untouched,
same ports as before) and no `requiem-fresh` volumes or networks remained. Use `--profile loadgen down -v`
when you have started the load generator.

## Not covered by this test

- A run from a fresh `git clone` on another machine (this ran in a git worktree of the same repo; the images were

- The Grafana dashboard contents were not inspected in this run, only that Grafana is up.
